# ADR 0002：M3 插件宿主与写路径边界

- 状态：**Accepted（2026-11-13）**——D1–D6 已在 M3 实现并有探针/文档证据；逐项核对见
  [M3 退出清单](../plan/M3-exit-checklist.md)（M3 = 退出候选，W6 真人点击验收待补）。
- 日期：2026-11-13
- 关联：[M3 范围](../plan/M3-scope.md)、[控制面文档](../CONTROL-PLANE.md)、[DEVICE-PLUGINS](../DEVICE-PLUGINS.md)、
  [ADR 0001](0001-m1-1khz-p99-limits.md)

## 背景

M2 已交付只读观测面（状态/字典/PDO/拓扑/指标/SSE/WebUI）与默认关闭的 `POST /pdo` 写开关。
M3 需要回答三个边界问题，避免控制面与插件继续无约束膨胀：

1. **插件宿主**：声明式 `plugin.yaml` 已覆盖多数设备；行为插件（CiA402 定制状态机、厂商协议）
   需要可执行代码。代码如何隔离、如何与实时环交互？
2. **SDO 写路径**：在线编辑对象字典（尤其厂商对象）是客户高频诉求，但会破坏"只读默认"安全模型；
   写路径如何授权、审计、限流？
3. **鉴权/TLS**：控制面当前无鉴权、仅建议回环；M3 是否在进程内做 TLS/鉴权？

## 决策

### D1 插件分两类，行为插件永不进实时环

- **声明式插件**（`plugin.yaml` + `facts.md`）：维持现状，由 `plugin-host` 在启动时编译为
  SII/对象字典/PDO 映射，无运行时开销。
- **行为插件**（WASM）：在 `plugin-host` 内的独立沙箱实例中运行，**不加入**线缆层实时循环。
  与实时环的唯一接口是**核心持有的 PDO 共享内存 arena**：插件在每周期后的"应用窗口"读写
  已映射字节，由核心在下一个周期前提交；插件不能直接访问寄存器/FMMU/邮箱/网络。
- 插件调用按"符号名 → PDO 偏移"映射，映射表来自 manifest；未知符号调用返回错误。
- 生命周期：插件按 generation 计数热加载/卸载；实时环只看到 generation 切换的原子指针，
  不做动态注册扫描。

### D2 行为插件的宿主 API（最小面）

只暴露：`read_pdo(symbol) -> bytes`、`write_pdo(symbol, bytes)`、`log(level, message)`、
`now_ms()`。不暴露：原始帧、寄存器地址、mailbox、文件/网络、时钟同步原语。
沙箱需限制内存、CPU 时间与 fuel；插件 panic/超时只隔离插件，不影响 ESC 内核。

### D3 SDO 写路径：显式开关 + 白名单 + 审计

- `POST /sdo` 仅在 `--serve-write` 启用，且**只允许**写 manifest 中声明 `writable: true`
  且不在安全排除表（身份对象 `0x1018`、SII/邮箱配置等）的对象；其他请求返回 403。
- 每次写记录审计事件（时间/来源地址/对象/旧值/新值）到控制面审计环形缓冲，`/metrics`
  暴露写次数；Web 端写操作需二次确认（M3 实现）。
- 写操作仍**无鉴权**；见 D4。默认只监听回环，文档明确"仅受信环境"。

### D4 鉴权/TLS：进程外终结，核心保持零依赖

- 控制面不引入 TLS 依赖，保持 Apache-2.0 OR MIT 与零外部 crate；生产部署由反向代理
  （nginx/traefik 等）终结 TLS 并做认证。
- M3 提供可选**静态 token**（`--serve-token-env VAR` 从环境变量读取，`Authorization: Bearer`），
  token 为空 = 当前无鉴权行为；token 仅防误触/内网隔离，不宣称生产级身份体系。

### D5 许可与依赖

- 行为插件运行时必须是宽松许可（如 wasmi MIT / wasmtime Apache-2.0 WITH LLVM-exception，需逐项核对），
  禁止 GPL/LGPL 进入核心；插件包本身许可由插件作者声明，不被核心分发。
- 硬件/厂商资产（ESI/PDF/固件）仍不入库；行为插件由用户本地加载。

### D6 明确非目标

- 不做"通过一致性测试/CTT 认证"的宣称；不做硬实时保证；不在 M3 内实现多租户/完整 RBAC。

## 备选方案与取舍

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 原生动态库（`.so`/`.dll`）插件 | 拒绝 | ABI/崩溃风险、无沙箱、跨平台打包困难 |
| 独立进程 + 本地 RPC | 保留为回退 | 隔离最好，但 PDO 共享内存/延迟成本高，先 WASM |
| 在插件内直接操作寄存器/帧 | 拒绝 | 破坏 ESC 内核对实时环的所有权 |
| 进程内 TLS/鉴权框架 | 拒绝 | 违背零依赖、扩大攻击面；交给反向代理 |

## 影响

- `plugin-host` 增加 WASM 宿主与 arena 接口（M3 工作流 1）；可能引入一个宽松许可 wasm 运行时依赖，
  需在 ADR 落地时复核许可与构建体积。
- 控制面新增 token 中间件与 `/sdo` 写路径（工作流 2/3）；`run-all-probes.sh` 增对应探针。
- M2 安全边界在 M3 收紧为"只读默认 + 写开关 + 白名单 + 审计 + 可选 token"。

## 未决问题

1. wasm 运行时选型（wasmi vs wasmtime）——先做 spike 比较启动时间/体积/许可与 MSRV。
2. PDO arena 的同步协议（双缓冲 + generation vs seqlock）——需性能与正确性 spike。
3. SDO 写白名单是否允许 manifest 声明"只读对象也可写"的调试豁免——倾向不允许。
